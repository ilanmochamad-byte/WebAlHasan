# Prompt handoff PRD V7 — Pengajuan Izin Orang Tua

Dokumen ini berisi prompt siap salin untuk **satu fase per giliran**. Claude Code mengimplementasikan; Codex mengaudit setelah Claude berhenti. Penetapan peran dan ruang lingkup ada di `AGENTS.md` dan `PRD-V7.md`. Menyiapkan lima pasang prompt ini bukan izin menjalankan lima fase sekaligus.

## Aturan pakai untuk semua fase

1. Berikan hanya prompt implementasi fase yang diperintahkan Human Developer. Setelah Claude commit/push dan berhenti, berikan prompt audit fase yang sama kepada Codex. Fase berikutnya menunggu keputusan audit dan instruksi Human Developer tersendiri. Jangan menjalankan kedua agen pada folder/branch yang sama secara bersamaan; jangan membuat worktree.
2. Sebelum Fase 1, verifikasi `origin/main`, branch spesifikasi `codex/prd-v7-spesifikasi`, serta commit keduanya. Jika spesifikasi belum masuk `main`, gunakan commit spesifikasi sebagai baseline hanya setelah membandingkannya dengan `origin/main` terkini dan memastikan perubahan lain tidak terlewat. Untuk Fase 2–5, mulai dari commit audit fase sebelumnya yang terverifikasi pada repositori terkait; catat hash nyata, jangan mengarang baseline. Jangan menulis di `main`.
3. Periksa `git status` dan perubahan milik pekerjaan lain sebelum berpindah branch atau commit. Baca `AGENTS.md`, `PRD-V7.md`, `PRD-V2.md`, audit V6 Fase 5, serta kode perizinan V2 yang benar-benar ada. Jika fase menyentuh aplikasi, baca pula `alhasanApps/AGENTS.md`, status dan baseline mobile, dan dokumentasi Expo untuk versi yang terpasang. Jangan memasukkan perubahan milik orang lain ke commit.
4. Gunakan data sintetis dan salinan MySQL/MariaDB untuk migrasi, rollback, dan pengujian. Jaga identitas dan relasi santri–wali, seluruh ID/riwayat izin V2, jalur pengurus V2, serta data V1–V6. Satu pengajuan wali memiliki satu ID `izin_pengajuan` sampai keputusan akhir; WhatsApp tetap OFF; tidak ada role login baru. Otorisasi, versi, idempotensi, dan konflik diputuskan di server.
5. Implementator mencatat hasil, hash, regresi, keterbatasan, dan handoff di `docs/phase-v7-N/README.md`; auditor mencatat uji independen, temuan, koreksi, keputusan lulus/belum lulus, dan batas bukti di `docs/phase-v7-N/AUDIT-CODEX.md`. Simpan ringkasan pada repositori mobile jika fase mengubah aplikasi. Jangan menyebut uji fisik, Push nyata, MySQL hosting, atau smoke cPanel lulus bila belum dijalankan.
6. Commit dan push hanya branch fase setelah pengujian yang tersedia. Jangan merge, migrasi/deploy produksi, mengirim rilis aplikasi, atau menyatakan gerbang akhir V6 tertutup karena pekerjaan V7. Bila suatu kriteria wajib belum terbukti, nyatakan terbuka dan berhenti untuk keputusan Human Developer.

## Fase 1 — Fondasi Pengajuan Wali dan Routing Pembimbing

### Prompt implementasi untuk Claude Code

> Implementasikan **hanya Fase 1 PRD V7** di WebAlHasan pada branch `claude/prd-v7-fase-1`. Baca `AGENTS.md`, `PRD-V7.md`, `PRD-V2.md`, `docs/prd-v7/prompts-implementasi-audit.md`, `docs/phase-v6-5/AUDIT-CODEX.md`, status Git dan kode/migrasi izin serta penugasan yang ada. Verifikasi baseline `origin/main` dan `codex/prd-v7-spesifikasi` sebelum membuat branch; jangan bekerja di `main` atau membuat worktree. Tambahkan skema aditif dan layanan web/API agar wali berelasi aktif membuat satu pengajuan kanonis dan membaca statusnya; tepat satu pembimbing sah melihat antrean, sedangkan nol/lebih dari satu masuk antrean admin untuk penetapan pembimbing sah. Murobi belum boleh menerima pengajuan sebelum diteruskan pembimbing. Terapkan otorisasi daftar/detail/mutasi, pemeriksaan benturan tanggal lintas jalur wali dan pengurus V2, idempotensi, versi, audit, serta perlindungan retry dan konkurensi. Pertahankan ID/data V2, `perizinan` warisan, relasi santri–wali, dan jalur pengurus. Uji migrasi/rollback dan preservasi pada salinan MySQL/MariaDB, HTTP/browser, wali pengaju/wali lain/wali asing, satu/nol/dua pembimbing, klik ganda, serta regresi V2 dengan fixture sintetis. Catat bukti, batas dan hash di `docs/phase-v7-1/README.md`; commit/push branch lalu berhenti untuk audit Codex. Jangan mengerjakan Fase 2, mengubah aplikasi tanpa kebutuhan fase, merge, atau deploy.

### Prompt audit untuk Codex

> Audit **hanya Fase 1 PRD V7** buatan Claude Code pada branch `claude/prd-v7-fase-1` setelah Claude berhenti. Baca `AGENTS.md`, `PRD-V7.md`, prompt ini, bukti implementator, baseline, dan semua commit fase. Uji independen migrasi/rollback pada salinan database, keutuhan ID/riwayat V2 dan relasi santri–wali, satu ID per retry, kunci sama dengan isi berbeda `409`, benturan rentang wali/pengurus secara bersamaan, serta otorisasi buat/daftar/detail/ID tebakan. Uji tepat satu/nol/dua pembimbing: hanya yang sah menerima antrean; kasus ambigu tetap di admin dan nol terlihat murobi. Pastikan wali lain hanya mendapat status ringkas dan admin hanya menetapkan pembimbing berpenugasan aktif. Jalankan regresi jalur pengurus V2 dan web/API. Koreksi temuan terarah beserta regresinya bila perlu; tulis `docs/phase-v7-1/AUDIT-CODEX.md` dengan keputusan dan batas nyata, commit/push branch yang sama, lalu berhenti. Jangan mulai Fase 2, merge, atau deploy.

## Fase 2 — Tinjauan Pembimbing, Perbaikan, dan Keputusan Akhir

### Prompt implementasi untuk Claude Code

> Implementasikan **hanya Fase 2 PRD V7** pada branch `claude/prd-v7-fase-2` dari commit audit Fase 1 yang terverifikasi. Baca `AGENTS.md`, `PRD-V7.md`, prompt ini, `docs/phase-v7-1/AUDIT-CODEX.md`, commit terbaru dan layanan keputusan V2. Lengkapi web/API untuk pembimbing aktif meminta perbaikan, menolak beralasan, atau meneruskan; hanya wali pengaju dapat memperbaiki dan mengirim ulang saat diminta atau membatalkan beralasan sebelum keputusan akhir. Penerusan harus mempertahankan ID pengajuan, memakai routing murobi V2, dan menahan kasus murobi tidak tunggal di antrean admin. Keputusan murobi atau admin pengganti memakai aturan V2; penolakan pembimbing tidak boleh ditulis sebagai `izin_keputusan` murobi. Terapkan versi/idempotensi, audit versi lama/baru, pemeriksaan ulang penugasan pada sesi lama, dan atomisitas pada balapan pembatalan–penerusan–keputusan. Uji MySQL/MariaDB salinan, konkurensi/retry, dua wali, murobi di luar cakupan, pembimbing dicabut, penolakan dan pelepasan benturan tanggal, serta regresi alur pengurus V2. Simpan bukti dan batas di `docs/phase-v7-2/README.md`, commit/push branch, lalu berhenti untuk audit Codex. Jangan mulai Fase 3, merge, atau deploy.

### Prompt audit untuk Codex

> Audit **hanya Fase 2 PRD V7** pada branch `claude/prd-v7-fase-2` setelah Claude Code berhenti. Baca `AGENTS.md`, `PRD-V7.md`, prompt ini, audit Fase 1, baseline dan semua commit Fase 2. Uji independen semua transisi pembimbing; hanya wali pengaju memperbaiki/membatalkan, wali lain hanya melihat status, versi lama atau kunci konflik ditolak tanpa perubahan. Pastikan penolakan pembimbing menutup permohonan tanpa keputusan murobi, penerusan membuat tepat satu antrean murobi/admin tanpa ID pengajuan baru, dan murobi di luar penugasan ditolak. Balapkan pembatalan dengan penerusan dan keputusan, termasuk retry, sampai terbukti satu hasil terminal dan paling banyak satu keputusan efektif. Uji pencabutan penugasan/relasi pada sesi lama, admin pengganti beralasan, serta regresi penuh jalur pengurus V2. Koreksi temuan terarah beserta regresinya bila perlu; catat keputusan dan batas di `docs/phase-v7-2/AUDIT-CODEX.md`, commit/push branch lalu berhenti. Jangan mulai Fase 3, merge, atau deploy.

## Fase 3 — Notifikasi, Laporan, dan Audit

### Prompt implementasi untuk Claude Code

> Implementasikan **hanya Fase 3 PRD V7** pada branch `claude/prd-v7-fase-3` dari commit audit Fase 2 yang terverifikasi. Baca `AGENTS.md`, `PRD-V7.md`, prompt ini, audit Fase 1–2, dan infrastruktur outbox/in-app/push V2. Tambahkan notifikasi tahap sesuai PRD: pembimbing/admin saat pengajuan masuk, wali pengaju saat dikembalikan/ditolak/diteruskan/diputus, dan murobi/admin routing saat diteruskan. Periksa ulang penerima, relasi dan penugasan sebelum kirim dan saat tautan dibuka; pesan push umum tanpa identitas atau alasan izin. Retry tidak boleh menggandakan pesan efektif; Push OFF/WhatsApp OFF menghasilkan nol request provider, sedangkan gagal kirim tidak membatalkan transaksi izin. Sediakan laporan web/API terfilter asal wali/pengurus, tahap, hasil, tanggal, cakupan dan durasi; angka, daftar, detail, ekspor memakai saringan peran yang konsisten. Audit setiap penetapan, versi isi, tindakan pembimbing, keputusan, pembatalan dan pengiriman tanpa token mentah/log sensitif. Uji fixture sintetis, outbox/retry, pencabutan hak pada sesi lama, laporan hitung tepat sekali, privasi payload/log, serta regresi Fase 1–2 dan V2. Tulis bukti/batas di `docs/phase-v7-3/README.md`, commit/push branch lalu berhenti untuk audit Codex. Jangan mulai Fase 4, merge, atau deploy.

### Prompt audit untuk Codex

> Audit **hanya Fase 3 PRD V7** pada branch `claude/prd-v7-fase-3` setelah Claude berhenti. Baca `AGENTS.md`, `PRD-V7.md`, prompt ini, audit Fase 1–2, bukti dan semua commit fase. Uji independen setiap peristiwa dan penerimanya, deduplikasi outbox/in-app/push pada retry, Push OFF dan WhatsApp OFF dengan nol request provider, rollback transaksi izin, serta akses tautan setelah wali/penugasan dicabut. Bandingkan kartu, daftar, ekspor dan detail laporan bagi wali pengaju, wali lain, pembimbing, murobi, admin dan pengguna asing dengan hitungan fixture yang sama. Periksa riwayat pelaku/waktu/alasan/versi dan pindai payload push/log agar tidak memuat nama santri, alasan, nomor telepon, atau token mentah. Jalankan regresi Fase 1–2 dan V2; koreksi terarah beserta regresinya bila perlu. Tulis keputusan/batas di `docs/phase-v7-3/AUDIT-CODEX.md`, commit/push branch lalu berhenti. Jangan mulai Fase 4, merge, atau deploy.

Uji paritas web/API/aplikasi, dua wali dan pengguna di luar cakupan, klik ganda, Android dan iOS sesuai build/perangkat yang benar-benar tersedia; bedakan emulator/simulator, perangkat fisik dan Push nyata.
