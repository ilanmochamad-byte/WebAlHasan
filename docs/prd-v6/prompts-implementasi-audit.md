# Prompt handoff PRD V6 — Keuangan Santri/BSA

**Keputusan Human Developer 25 Oktober 2026:** Claude Code mengimplementasikan, Codex mengaudit. Jalankan **satu** prompt implementasi, lalu **satu** prompt audit untuk fase yang sama. Fase berikutnya hanya dimulai sesudah audit sebelumnya menyatakan kriteria wajib terpenuhi dan Human Developer memberi instruksi baru. Prompt ini adalah bahan handoff, bukan izin untuk menjalankan semua fase, merge, migrasi/deploy produksi, atau merilis aplikasi.

## Aturan pakai untuk semua prompt

1. Gunakan folder proyek yang sudah ada; tidak perlu worktree. Jangan bekerja bersamaan dengan agen lain pada folder/branch yang sama. Periksa `git status` dan jangan menyentuh berkas tidak terkait. Jangan melakukan implementasi pada `main`.
2. Sebelum Fase 1, pastikan baseline remote **memuat** `PRD-V6.md`, keputusan V6 di `AGENTS.md`, dan dokumen ini. Jika spesifikasi belum di-merge, gunakan branch spesifikasi `codex/prd-v6-spesifikasi` sebagai baseline hanya setelah memastikan ia masih cocok dengan `origin/main` terbaru; jangan mengarang hash atau menimpa perubahan orang lain.
3. Untuk Fase 2–5, mulai dari **commit audit fase sebelumnya yang terverifikasi** pada repositori terkait. Periksa status V5 dan baseline mobile yang benar; audit lokal V5 tidak boleh disebut bukti rilis produksi. Catat hash yang nyata di dokumen fase. Catatan larangan V6 dalam `alhasanApps/AGENTS.md` berasal dari handoff V5 dan berlaku untuk sesi V5 tersebut; pada sesi V6 ikuti instruksi terbaru Human Developer, `AGENTS.md` web, dan `PRD-V6.md`, lalu selaraskan catatan mobile bila implementasi Fase 4 benar-benar dimulai.
4. Simpan bukti implementasi dan batas uji di `docs/phase-v6-N/README.md`; auditor menyimpan `docs/phase-v6-N/AUDIT-CODEX.md`. Jika fase menyentuh mobile, simpan handoff yang relevan pada kedua repositori. Gunakan fixture sintetis, salinan basis data, dan kanal notifikasi uji.
5. Commit serta push hanya branch fitur setelah pekerjaan fase selesai. Auditor dapat mengoreksi temuan secara terarah beserta regresinya. Bila uji perangkat, hosting, atau provider tidak tersedia, tulis **belum diuji**; jangan menyebutnya lulus. Jangan merge/deploy/migrasi produksi atau memulai V7.
6. Tagihan dan tabungan **tidak boleh dirilis terpisah**. Fase 1–4 dapat diuji di lingkungan uji; keputusan rilis bersama berada setelah audit Fase 5 dan keputusan Human Developer.

## Fase 1 — Fondasi BSA dan Transaksi Minimum

Pastikan baseline memuat spesifikasi V6; verifikasi hash `origin/main` dan branch spesifikasi sebelum membuat branch, tanpa bekerja di `main`. Buat satu penugasan BSA, migrasi aditif, layanan dan web/API minimum agar admin dapat menugaskan BSA dan petugas dapat menerbitkan satu tagihan, mencatat setoran/penarikan, serta membaca saldo. Jaga ID/relasi santri–wali dan data PSB/V1–V5; terapkan otorisasi server, nominal eksak, saldo tidak negatif, idempotensi, serta konkurensi. Uji migrasi/rollback pada salinan MySQL/MariaDB, HTTP/API, dan tampilan web dengan fixture sintetis; mobile hanya dibaca untuk baseline. Catat hasil, batas, hash, serta langkah pemulihan di `docs/phase-v6-1/README.md`, commit dan push branch, lalu berhenti untuk audit Codex. Jangan mengerjakan Fase 2, merge, migrasi/deploy produksi, atau merilis aplikasi.

### Prompt audit untuk Codex

> Audit **hanya Fase 1 PRD V6** buatan Claude Code pada branch `claude/prd-v6-fase-1`. Baca `AGENTS.md`, `PRD-V6.md`, `docs/prd-v6/prompts-implementasi-audit.md`, bukti implementator, baseline, dan seluruh commit fase; pastikan Claude sudah berhenti sebelum Anda mengubah checkout. Jalankan pengujian independen terhadap penugasan BSA, satu tagihan, setoran/penarikan, saldo tidak negatif, kiriman ganda, dua penarikan bersamaan, pencabutan penugasan, isolasi wali, serta migrasi/rollback dan preservasi data pada salinan database. Periksa web/API dan batas peran; jangan menerima hasil implementator sebagai bukti audit Anda sendiri. Koreksi temuan secara terarah beserta regresinya bila perlu. Tulis hasil lulus/belum lulus dan batas nyata di `docs/phase-v6-1/AUDIT-CODEX.md`, commit dan push branch yang sama, lalu berhenti. Jangan memulai Fase 2, merge, atau deploy.

## Fase 3 — Tabungan Lengkap dan Pembayaran Silang

### Prompt implementasi untuk Claude Code

> Implementasikan **hanya Fase 3 PRD V6** pada branch `claude/prd-v6-fase-3` dari commit audit Fase 2 yang terverifikasi. Baca `AGENTS.md`, `PRD-V6.md`, dokumen audit Fase 1–2, dan commit terbaru. Uji dua penarikan/pembayaran bersamaan, retry, kegagalan di antara dua pencatatan, koreksi transaksi terkait tagihan, otorisasi wali, rekonsiliasi, dan regresi Fase 1–2/PSB di MySQL/MariaDB salinan. Simpan bukti, batas, dan hash di `docs/phase-v6-3/README.md`, commit/push, lalu berhenti untuk audit Codex. Jangan mulai Fase 4, merge, atau deploy.

### Prompt audit untuk Codex
