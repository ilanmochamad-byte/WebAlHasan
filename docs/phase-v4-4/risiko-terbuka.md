# Risiko dan batas uji Fase 4

- Diaudit Claude Code 16 Oktober 2026 (lihat `audit-claude.md`); hasil audit bukan putusan merge/produksi. Fase 5 belum dikerjakan; mobile tetap bersih pada `main` / `dfae26d`.
- Aktual: MariaDB **12.3.2**, PHP **8.4.14**, Chromium Playwright lokal pada desktop/375 px/teks 24 px. MySQL lain, MariaDB hosting 10.6.24, cPanel, Apache nyata, Safari, perangkat fisik/iOS/Android belum diuji. Guard URL privat diuji melalui router PHP lokal; `.htaccess` ditinjau tetapi belum dibuktikan di hosting.
- Seluruh provider menggunakan mock. Tidak ada pengiriman push fisik/Expo/FCM/APNs, receipt nyata, WhatsApp nyata, atau smoke produksi. Tiket mock bukan bukti pengantaran fisik. Kompatibilitas notifikasi mobile lama tidak sama dengan alur V4 mobile; integrasi layar/deep-link tetap Fase 5.
- Database dan filesystem tidak atomik. Uji mencakup penulisan parsial, kegagalan insert kode/outbox/audit dan crash proses sesudah write/fsync sebelum commit. **Belum** menyuntikkan putus koneksi pada saat jawaban COMMIT hilang, kegagalan disk/power-loss, fsync direktori, atau backup/restore hosting. Penanganan commit ambigu mempertahankan berkas ketika DB tidak dapat diperiksa. Rekonsiliasi read-only; pemulihan memerlukan operator. Missing/corrupt PDF ditolak 503, tidak diregenerasi/diganti diam-diam.
- SERIALIZABLE dan penguncian sumber dipertahankan selama render PDF: konservatif, dapat menahan penulis nilai/absensi/otorisasi. Konflik 1020 pada MariaDB benar-benar muncul dan diselesaikan retry terbatas. Kunci update satu sumber absensi diuji; seluruh variasi insert peserta/pertemuan/ubah master/penugasan bersamaan dan beban besar belum dibenchmark. Setelah commit, perubahan sumber hidup tidak mengubah snapshot/PDF; koreksi formal tetap memerlukan Buka/Ganti.
- DB mengandalkan InnoDB dan enforcement CHECK. Rollback hanya kosong; guard SQL yang ditolak dapat meninggalkan tabel guard kosong (DDL tidak transaksional), tanpa menghapus bisnis. Hosting/restore produksi belum diuji. Tidak menghapus residu suite V1–V3 untuk membuat verifier tampak bersih.
- Warisan: `phase5_static` gagal membaca `alhasanApps/src/app/(app)/(reports)/reports.tsx` setelah redesain. 14 integrasi V1–V3 dan 14 statis lainnya lulus. Warning dari satu suite warisan itu tidak disamakan dengan log HTTP Fase 4 (0 warning/fatal).
- Gate Fase 3 mempertahankan nol pertemuan sebagai nol hitungan lengkap, dengan penyerahan/verifikasi manual. Preview memperlihatkan jumlah pertemuan, tidak membuat Alpa/pertemuan sintetis. Tidak mengubah keputusan ini diam-diam.
- Finalisasi/mutasi rapor memakai rencana semester aktif sesuai fondasi Fase 3. Pembacaan wali historis tetap melalui relasi aktif; petugas memakai resolver capability. Prosedur koreksi semester yang sudah dinonaktifkan serta perpindahan kelas ambigu tetap memerlukan penyelesaian administratif, bukan bypass gate.
- Daftar wali dibatasi 200 rapor; matriks/opsi/riwayat petugas belum pagination/benchmark kelas besar. Snapshot menyertakan byte tanda tangan privat; DB dan cadangan membutuhkan kontrol akses yang sama dengan PDF. Bukan tanda tangan bersertifikat kriptografis.
- Pengunggahan dibatasi aplikasi 10 MB dan 20 pemeriksaan/IP/menit. PHP/hosting dapat menetapkan batas lebih rendah; uji server memakai upload_max_filesize=10M/post_max_size=12M. Jika post_max_size terlewati sebelum PHP mengisi form, CSRF dapat menolak 419. Reverse proxy/NAT berbagi IP dapat berbagi kuota; X-Forwarded-For tidak dipercaya. WAF/body/access-log eksternal hosting belum diperiksa. Aplikasi sendiri tidak menyimpan unggahan atau log kode QR/body; QR memakai fragment.
- Sakelar dan dedup/retry outbox/receipt lokal diuji. Penerima tanpa perangkat dapat mendapat outbox Push yang kemudian gagal permanen; InApp tetap tersedia. Seperti fondasi V2, retry jaringan setelah provider menerima pesan tetapi jawaban hilang dapat mengirim pesan eksternal lagi; tidak mengklaim exactly-once pengantaran provider. Tepat-satu yang dibuktikan adalah versi/PDF/QR/InApp/outbox per event wali.
- Tanda tangan PNG sintetis diuji; JPEG/WebP diterima oleh fondasi unggah dan dependensi, tetapi belum diuji dengan tanda tangan operasional. Persetujuan nyata penanda tangan berada di luar aplikasi sesuai PRD.
- (Audit) Router PHP lokal hanya meniru aturan direktori `.htaccess`; `composer.json/lock` dan `PRD-V4.md` terlayani 200 secara lokal dan hanya ditolak oleh `FilesMatch` Apache, yang belum dibuktikan di hosting.
- (Audit) Ganti/Tarik/Buka mensyaratkan semester `Aktif`; rapor semester yang sudah ditutup belum dapat ditarik lewat aplikasi.
- (Audit) Target ketuntasan tampil dua desimal ("75.00"); snapshot API wali memuat ID internal pembimbing/murobi. Keduanya nonblokir dan dapat diputuskan pada Fase 5.
